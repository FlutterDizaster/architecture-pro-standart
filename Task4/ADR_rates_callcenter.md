### Название задачи: ADR-2. Передача актуальных ставок в кол-центр банка и партнёрский кол-центр
### Автор: Дмитрий Логинов, команда цифровой трансформации
### Дата: 12.11.2026

Решение опирается на MVP из ADR-1 (`Task3/ADR_deposits_MVP.md`): справочник ставок уже в АБС, ставки публикуются в Kafka сервисом интеграции депозитов.

### Функциональные требования

| № | Действующие лица или системы | Use Case | Описание |
| :-: | :- | :- | :- |
| 1 | Менеджеры бэк-офиса, АБС, сервис интеграции депозитов, Kafka | Публикация ставок | 1. Менеджер бэк-офиса утверждает новые ставки в справочнике АБС. 2. Сервис интеграции забирает изменение и публикует полный актуальный набор ставок в `deposit.rates`. |
| 2 | Оператор кол-центра банка, система кол-центра, Kafka | Консультация по ставкам в кол-центре банка | 1. Модуль ставок системы кол-центра читает `deposit.rates` и сохраняет последнюю версию в свою БД. 2. Клиент звонит и спрашивает про депозит. 3. Оператор открывает карточку звонка, виджет показывает текущие ставки и время их обновления. 4. Оператор консультирует клиента и при желании заводит заявку. |
| 3 | Сервис интеграции депозитов, SFTP-сервер банка | Выгрузка ставок для партнёра | 1. При каждом изменении ставок и каждое утро в 8:00 сервис формирует CSV-файл. 2. Загружает его на SFTP-сервер во временное имя и переименовывает в `rates_latest.csv`, копию кладёт в архив с датой и временем в имени. |
| 4 | Система партнёрского кол-центра, оператор партнёра | Консультация по ставкам у партнёра | 1. Система партнёра по своему расписанию забирает `rates_latest.csv` по SFTP. 2. Оператор партнёра видит ставки и время их актуальности и консультирует клиента по скрипту банка. |
| 5 | Система партнёрского кол-центра, администратор SFTP | Ставки не обновились | 1. Если файл старше суток, система партнёра показывает оператору предупреждение. 2. Банк получает алерт, если выгрузка не прошла: сервис интеграции пишет ошибку в мониторинг. |

Формат файла: CSV в UTF-8, разделитель точка с запятой. Колонки: код продукта, название, срок в днях, минимальная сумма, ставка, дата начала действия, время выгрузки. Персональные надбавки в файл не попадают, это данные клиентов.

### Нефункциональные требования

| № | Требование |
| :-: | :- |
| 1 | Кол-центр банка видит новые ставки не позже чем через минуту после утверждения |
| 2 | У партнёра ставки отстают не больше чем на интервал его опроса, но файл обновляется при каждом изменении и минимум раз в день |
| 3 | Система кол-центра показывает ставки, даже если АБС или Kafka недоступны: берёт последнюю сохранённую версию и показывает время обновления |
| 4 | Нагрузки на БД АБС от кол-центров нет, ставки читаются из Kafka и из файла |
| 5 | Партнёр получает только публичные ставки, без данных клиентов |
| 6 | SFTP-сервер стоит в DMZ, доступ по ключу и только с IP-адресов партнёра, вход в сеть банка партнёру не нужен |
| 7 | Партнёр не может вызывать API банка, поэтому обмен только файлами |
| 8 | Систему кол-центра дорабатывают Java-специалисты банка через механизм расширений, подрядчика не привлекаем |

### Решение

Диаграммы:

- `C4_context_rates_callcenter.png`: контекст, исходник `.puml`;
- `C4_components_rates_callcenter.png`: компоненты сервиса интеграции депозитов и нового модуля системы кол-центра.

Ставки уже есть в Kafka после MVP, поэтому кол-центр банка просто подписывается на тот же топик `deposit.rates`. Новый модуль ставок на Spring Boot подключается через механизм расширений платформы, хранит последнюю версию в PostgreSQL системы кол-центра и отдаёт её по REST, а новый виджет в React-интерфейсе оператора показывает ставки в карточке звонка. В топик всегда уходит полный набор ставок, а не дельта, так что модулю не нужно ничего склеивать и после простоя хватает последнего сообщения.

С партнёром API нет, он готов принимать только файлы. Выгрузку делаю в сервисе интеграции депозитов, потому что он и так первым узнаёт об изменении ставок: триггер в БД АБС пишет событие, сервис забирает его через несколько секунд. Файл кладём на SFTP-сервер в DMZ, партнёр забирает его сам. Файл пишется во временное имя и переименовывается, чтобы партнёр не прочитал его наполовину. Выгрузка идёт и при изменении, и по утрам, чтобы даже без изменений у партнёра был свежий файл с датой.

В MVP это добавляет: SFTP-сервер, компонент выгрузки в сервисе интеграции, модуль ставок в системе кол-центра. Задачи вошли в общий список ниже и в `RoadMap.drawio`.

### Альтернативы

1. Кол-центр банка ходит за ставками в REST API депозитного сервиса. Тоже рабочий вариант, но добавляет синхронную зависимость кол-центра от интернет-банка. Kafka уже есть, подписка проще и переживает простой источника.
2. Отправлять партнёру файлы по почте, как сейчас скрипты звонков. Дёшево, но вручную, без контроля доставки и с риском, что партнёр будет работать по старому файлу. Отказался.
3. Отдельный сервис выгрузки вместо компонента в сервисе интеграции. Чище по разделению, но ради одной задачи ещё один сервис на сопровождении. Для MVP оставляю компонентом, вынести можно позже.
4. Отдавать партнёру файл по HTTPS-ссылке. Технически возможно, но партнёр готов забирать файлы, а SFTP для файлового обмена привычнее и проще закрыть по ключам и IP. Выбрал SFTP.

**Недостатки, ограничения, риски**

- У партнёра ставки могут отставать на интервал его опроса SFTP, мы на это не влияем. Договариваемся об интервале не реже раза в 15 минут.
- В кол-центрах видны только общие ставки. Персональную ставку оператор не назовёт, клиента нужно отправлять в интернет-банк или в отделение.
- SFTP-сервер в DMZ нужно сопровождать: ключи, обновления, мониторинг. Это новая точка входа извне, её проверит ИБ.
- Модуль в системе кол-центра зависит от механизма расширений платформы подрядчика. При обновлении платформы модуль придётся проверять.

### Крупные задачи по системам

Номера совпадают с `RoadMap.drawio`. Задачи T1–T16 входят в MVP на 6 месяцев, T17–T27 в целевое решение на год.

Инфраструктура IT

- T1. Kafka-кластер в двух ЦОД, мониторинг, права на топики.
- T2. API-шлюз nginx в двух ЦОД, TLS-сертификаты, ограничение частоты запросов с сайта.
- T3. SFTP-сервер в DMZ, ключи и белый список IP партнёра.

АБС

- T4. Справочник ставок в БД АБС с ролями для депозитного и кредитного бэк-офисов, экраны в Delphi.
- T5. Хранимые процедуры создания заявки и смены статусов, экран очереди онлайн-заявок.
- T6. Ночной расчёт персональных надбавок для клиентов интернет-банка.
- T17. Правила автоматического подтверждения ставки и открытия депозита без бэк-офиса.
- T18. Открытие депозита в отделении по справочнику ставок, без запроса в бэк-офис.
- T27. Номер онлайн-заявки при заведении нового клиента и счёта в отделении, чтобы конвейер связал заявку с клиентом (Task5).

Сервис интеграции депозитов

Интернет-банк

Сайт

Кредитный конвейер и скоринг

- T21. Приём онлайн-заявок из Kafka, новый процесс, публикация статусов, условий кредитов и результатов скоринга (Task5).
